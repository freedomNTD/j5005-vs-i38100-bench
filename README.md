# OpenWrt 软路由实测对比：Pentium Silver J5005 vs Core i3-8100

同一套自build固件下，两台常见软路由硬件的 CPU / 内存 / 温度 / 指令集实测对照。
用途：给"低功耗移动核（Apollo Lake）够不够做路由器、什么时候该上桌面级核"提供可复现的数字。

## 测试环境

| 项 | 设备 A | 设备 B |
|---|---|---|
| CPU | Intel Pentium Silver **J5005**（4C4T，Goldmont，基频 1.5GHz / 上限 2.8GHz） | Intel Core **i3-8100**（4C4T，Coffee Lake，3.6GHz） |
| TDP（规格，非实测） | 10 W | 65 W |
| 内存 | 3.4 GiB | 15.1 GiB |
| 固件 | OpenWrt 24.10.8 (r29233) | OpenWrt 24.10.8 (r29233)（同一份 buildroot 产出） |
| 内核 | 6.6.144 | 6.6.144 |
| 频率策略 | `schedutil` | `powersave`（intel_pstate） |

两台机器跑**同一份脚本**、同一数据量（400 MB / 路），计时用 `/proc/uptime`（该 BusyBox 的 `date` 不支持 `%s%N`，用它会算出 0）。
所有测试都是纯 CPU/内存负载，不写盘、不影响转发。

## 结果

### 标量吞吐（BusyBox `md5sum` / `sha256sum`，单核 400 MB）

| 指标 | J5005 | i3-8100 | i3-8100 / J5005 |
|---|---|---|---|
| 单核 md5 | 5.73 s → **70 MB/s** | 1.76 s → **227 MB/s** | **3.24×** |
| 单核 sha256 | 5.77 s → **69 MB/s** | 2.11 s → **189 MB/s** | **2.74×** |
| 4 路并行 md5（共 1600 MB） | 8.27 s → **193 MB/s** | 2.72 s → **588 MB/s** | **3.05×** |
| 核间扩展比（4 路 / 单核） | 2.76× | 2.59× | — |

### 指令集（取自 `/proc/cpuinfo`，只看关键项）

| | J5005 | i3-8100 |
|---|---|---|
| AES-NI | ✅ | ✅ |
| SSE4.1 / SSE4.2 | ✅ | ✅ |
| **AVX / AVX2** | ❌ | ✅ |
| BMI1 / BMI2 / ADX | ❌ | ✅ |
| **SHA-NI** | ✅ | ❌ |
| RDRand | ✅ | ✅ |

值得单独指出：**Goldmont 是 x86 上最早带 SHA 扩展的核之一**，所以 J5005 有 `sha_ni` 而桌面级的 i3-8100 反而没有（`sha_ni` 到 Ice Lake / Comet Lake 才回到消费级产品线）。纯 SHA 类负载上 J5005 相对不吃亏；但 i3-8100 独有的 **AVX2 + BMI2** 在一切向量化负载（压缩、TLS 批量、本地模型推理）上是量级差距——而本文的标量基准**恰恰测不到这部分**，也就是说真实差距比 3× 更大。

### 温度

| | 数值 | 场景 |
|---|---|---|
| J5005 | 73 °C | 并行压测进行中（小机箱被动/小风扇） |
| i3-8100 | 27.8 °C | 空闲 |

两者不可直接同场景比较（一个是负载中、一个是空闲），但反映出实际部署差异：**J5005 的持续性能受热与功耗封顶**，短时能冲到 2.8 GHz、长压会回落；i3-8100 有充足的散热余量维持满频。

### 旁证：SSH 通道吞吐（**不能当结论**）

设备 A ↔ 设备 B 之间拉 200 MB：

- 直连设备 A：3.21 s → 62 MB/s
- 经设备 A 跳板到设备 B（两跳，设备 A 需做两份加解密）：2.45 s → 81 MB/s

设备 B 在"多一跳 + 对端还要替我做代理加解密"的不利条件下仍然更快，方向与 CPU 基准一致。但这个数字**不能当作 AES 吞吐或转发吞吐**：它混入了 SSH 握手、管道缓冲，且 OpenWrt 默认的 dropbear 未必走 AES-NI 路径。

## 结论 / 选型

- **纯转发场景（NAT + 防火墙 + 广告 DNS）两者都够用**，千兆线速对 J5005 不是压力；实测连接跟踪表仅数十条，远未触及瓶颈。
- **需要内存与向量化的负载应放在 i3-8100 上**：Docker、本地 LLM/TTS、镜像/PXE 这类工作负载，16 GB 内存与 AVX2 的收益远大于功耗代价。
- **J5005 的价值在 10 W 常驻功耗**和自带的无线平台（可作为无线上行/热点），适合做分支节点或第二路由，不适合承担重计算。
- 部署建议：给 J5005 这类被动散热小主机留出热余量（持续压测会掉频），并在固件侧确认 `schedutil` 之外是否需要更激进的性能策略。

## 复现

```sh
sh bench-box.sh      # 在两台 OpenWrt 上分别执行
```

脚本见 [`bench-box.sh`](./bench-box.sh)：`head -c 400MB /dev/zero | md5sum`、并行 4 路，读 `/proc/cpuinfo`、`/sys/devices/system/cpu/*/cpufreq/*`、`/sys/class/thermal/*`。无外部依赖，BusyBox 即可运行。

## 已知测量局限

1. md5/sha256 用的是 BusyBox 标量实现，**不走 SHA-NI、不走 SIMD**，因此测的是 IPC × 频率，不代表硬件加速后的密码吞吐。
2. 未测真实 NAT 转发容量（需要被测路由下游有一台客户端并施加线速流量）、未测 WireGuard / IPsec 吞吐。
3. 温度两行不是同场景对比。
4. 单次采样，未做多轮取中位数。
